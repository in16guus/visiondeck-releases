Support

Common issues, FAQs, and how to get help.

The Vision Pro doesn't find my Mac

The headset discovers the Mac via Bonjour on the local network. Check:

  • Mac and Vision Pro are on the same Wi-Fi. Different networks (e.g., a guest network) won't see each other.
  • VisionDeck is running on the Mac. The menu-bar icon should say "Waiting for Vision Pro…" or "1 Vision Pro connected."
  • No firewall is blocking it. macOS may prompt to "Allow incoming connections" the first time — say yes.
  • Your router doesn't isolate clients (sometimes called "AP isolation"). Many enterprise networks do this — try a personal hotspot to confirm.

Screen Recording permission denied

VisionDeck needs Screen Recording to capture your displays. To grant:

  1. Open System Settings ▸ Privacy & Security ▸ Screen Recording.
  2. Enable VisionDeck in the list.
  3. If the toggle is greyed out, click the lock and authenticate first.
  4. Return to VisionDeck. If macOS requests a relaunch, relaunch the app once.

If VisionDeck doesn't appear in the list, open the Mac app and choose Grant Screen Recording Access. This explicit action opens the system permission flow.

The screen is black or shows a placeholder forever

  • Confirm the Mac is actually streaming (menu-bar icon).
  • Move the headset to a different Wi-Fi position — high packet loss can stall the stream.
  • Quit and relaunch the Vision Pro app. It auto-reconnects, but a fresh restart can clear stale state.

The Mac app reopens the "unidentified developer" warning

This shouldn't happen with the notarized DMG. If it does, the DMG may have been re-downloaded with a quarantine flag set incorrectly. Re-download from GitHub Releases and re-install.

The host keeps re-prompting for Screen Recording

macOS ties the Screen Recording grant to the app's code signature. If you're running an unsigned build (built from source without Xcode auto-signing in), every rebuild changes the signature and re-prompts. Either:

  • Use the notarized DMG (signed with a stable Developer ID — the grant persists), or
  • Run ./scripts/build-host.sh which signs with a stable Apple Development identity.

Auto-update isn't working

The Mac app checks for updates via Sparkle when launched. If it's stuck:

  • Click VisionDeck ▸ Check for Updates… manually.
  • Confirm you have an internet connection.
  • If you launched from the DMG directly without dragging to Applications, Sparkle can't replace the bundle. Drag the app to Applications first.

Performance feels stuttery

  • Lower the resolution of peripheral screens in the in-headset Configure panel.
  • Reduce the number of active screens (the dock has a +/- stepper).
  • Move the Mac closer to your Wi-Fi router. 5 GHz or Wi-Fi 6/6E gives the best results.

Audio crackles or briefly drops out

  • Confirm that Mac and Vision Pro have a strong, low-loss Wi-Fi connection; avoid guest networks and congested 2.4 GHz channels.
  • Temporarily reduce active display count to separate network saturation from an audio-device problem.
  • Disconnect Bluetooth audio devices from the Mac and test the built-in output once.
  • If the issue repeats several times per second, stop using that build and file an issue with a timestamp and Console logs. Repeated crackling does not meet the release quality gate.

Still stuck? File an issue

Open a GitHub issue at github.com/in16guus/visiondeck-releases/issues. Please include:

  • macOS version (26.5 or later)
  • visionOS version (26.5 or later)
  • VisionDeck version (visible in About VisionDeck)
  • What you tried and what happened
  • Any error messages in Console.app filtered by VisionDeck
